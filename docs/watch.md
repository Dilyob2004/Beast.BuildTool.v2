# Пересборка при изменениях (watch) и версии

## `beast watch`

```bash
beast watch [проект] [--target <цель>] [--platform ...] [--config Debug] \
    [--on-success "<команда>"] [--versioned] [--device <serial>] [--debounce 300]
```

`watch` собирает цель и затем следит за `Source/` и `Config/` проекта и всех его внешних проектов
(`externalProjects`). После изменения выжидается пауза `--debounce` (300 мс по умолчанию), чтобы серия
сохранений дала одну сборку. Одновременно идёт только одна сборка; изменения, сделанные во время неё,
собираются сразу после. Каталоги `Intermediate`, `Binaries`, `.git`, `.vs`, временные файлы редакторов
(`.swp`, `~`, `.tmp`) сборку не запускают. Правила (`*.Build.cs`, `*.Target.cs`) и `BuildConfig.json`
вычисляются заново при каждой сборке.

Ошибка компиляции выводится как обычно, а `watch` продолжает работать и ждёт следующего изменения.
Остановка — Ctrl+C.

### После успешной сборки

`--on-success "<команда>"` выполняется оболочкой (`/bin/sh -c`, на Windows `cmd /c`) в каталоге
проекта, с переменными:

| Переменная | Значение |
|---|---|
| `BEAST_BUILD` | номер сборки в этом запуске `watch` (1 — первая) |
| `BEAST_PROJECT`, `BEAST_TARGET` | проект и цель |
| `BEAST_PLATFORM`, `BEAST_CONFIGURATION` | платформа (`Windows`, `Linux`, `Mac`, `Android`…) и конфигурация |
| `BEAST_BINARIES` | `Binaries/<platform>/<config>` |
| `BEAST_HOT_LIBRARIES` | с `--versioned`: пути новых копий библиотек через `;` (Windows) или `:` |

Ненулевой код выхода команды только выводится как предупреждение.

### Версионные библиотеки для горячей подмены (`--versioned`)

Хост, загрузивший `Game.dll`, держит файл открытым, и компоновщик не может его перезаписать. С
`--versioned` после каждой успешной сборки разделяемые библиотеки цели и её целей-зависимостей
копируются в `Binaries/<platform>/<config>/Hot/` под номером сборки: `Game.3.dll` (и `Game.3.pdb`),
`libGame.3.so`, `libGame.3.dylib`. Файл `Hot/<имя>.latest` содержит имя новейшей копии — хост может
опрашивать его или получить путь из `BEAST_HOT_LIBRARIES`. Хост загружает копию, а не оригинал, поэтому
следующая сборка перезаписывает оригинал без конфликта. Старые копии не удаляются (одна из них может
быть ещё загружена).

На Android (`--platform Android`, цель — приложение) новые `.so` (библиотека приложения и разделяемые
зависимости) отправляются на устройство: `adb push` во временный каталог и `run-as <applicationId> cp`
в `files/hot/` приложения (нужна debug-сборка, `run-as` требует debuggable). `--device` выбирает
устройство, если их несколько.

Сама подмена модуля в процессе (загрузка новой копии, перенос состояния, проверка ABI) — забота хоста,
то есть приложения или SDK; Beast только собирает и доставляет файлы.

## Минимальная версия Beast для проекта

```json
// Config/BuildConfig.json
"minimumBuildToolVersion": "2.1.0"
```

Если Beast старее, любая команда, читающая конфигурацию проекта, останавливается с сообщением, какая
версия нужна и какая установлена. Сборки из исходников (`2.1.0-dev+<commit>`) считаются своей базовой
версией. Версия инструмента: `beast --version`; релизы — теги `v2.x.y` (workflow `Release`, см.
[Установка](install.md)).
